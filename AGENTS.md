# Working on corboc

For every Corbo-related repository, use `Jabar` as the user’s Git author and
committer name, preserving the configured email. Prefer the local or Corbo-specific
conditional Git configuration over changing unrelated repository identities.

This repository owns the compiler. The language specification, STD and readable
runtime are versioned separately by `corbo.lock`.

Before validation or test changes, prepare the pinned sources and read
`.deps/corbo/docs/VALIDATION_GUIDELINES.md` and
`.deps/corbo/docs/LANGUAGE_RULES.md`. Obtain explicit agreement before changing
normative language rules. The Rust frontend is frozen and remains in the
language repository.

Classify modifications as compiler/core, API/STD, or build/organization changes.
Validate affected mechanisms and directly related regressions proportionately;
do not turn an API or organization change into a new adversarial campaign.
A separate lab owns deep rule-breaking analysis and mutation campaigns.

Maintain docs/IMPLEMENTATION_CHECKLIST.md, docs/VERIFICATION_MATRIX.md and cycle
reports. Show the checklist at significant steps, mark validation complete only
when execution finishes, and report precise platform limits. Passing tests do
not prove the language safe. Windows ARM64 execution remains explicitly deferred.

Edit readable runtime implementations in the language repository, update the
locked commit deliberately and regenerate src/runtime_sources/runtime_sources.crb.
Do not edit the generated byte arrays by hand or keep another runtime copy here.
