# Documentation coverage integration

Date: 2026-11-19. Scope: compiler/core implementation of existing rules,
plus the directly affected resource-packing and documentation tooling.
No grammar, normative rule, STD API or runtime algorithm changed. The frozen
Rust frontend was not modified.

## Completed implementation

| Reported form | Implementation | Executed result |
| --- | --- | --- |
| Direct shared-reference return | Explicit borrowed arguments retain their temporary root/parent in the returned-loan contract and liveness traversal. | 42; a second forwarding call also prints 42. |
| Function structural contract | Concrete function specialization uses structural signature checks, inferred output parameters and dependent recipe ordering. | 42; two concrete types print 20 and 22; inferred output and forwarding print 42. |
| Custom branch wrapper | Branch metadata is separate from signature children, its completion method is resolved, and join accepts a temporary handle expression once. | Original package exits successfully; the result variant prints 42. |
| C address operand | Raw-address traversal recognizes the unchecked C boundary as well as assembly. | The C write changes the array byte to 42; escaping an address is refused. |
| Numeric try_from | A typed Result helper checks representability before every potentially narrowing C cast. | 255; integer bounds and exact integer/float conversions select the expected variants. |
| Typed borrowed text length | &str annotations and byte_len use the existing text descriptor. | 2. |
| Borrowed slice content_eq | Named borrowed-slice arguments use the same liveness and passing checks as explicit slice expressions. | true. |
| Mutable lock receiver | Lock metadata preserves signature order; returned record fields map to caller-side roots; through-result reservation persists until cleanup; compound writes resolve stored mutable references. | 43; explicit drop releases the reservation; shared writes and a second reservation are refused. |
| Custom buffered sink | usize is an ordinary fixed scalar in a record, while raw addresses retain separate provenance. | Original package exits successfully; buffered flush reports two bytes written. |

Numeric conversions are expanded together in one source pass. The focused
numeric program contains five conversions, including an out-of-range f64 to
f32 input. Range checks precede that narrowing float cast; batching prevents
one rewrite workspace from accumulating per call.

Function contracts specialize concrete calls before ordinary checking and
placement. Returned records reuse the independent field-value graph already
used for tuple components. Lock reservations are metadata in that graph; no
synchronization implementation is generated by an annotation.

The growing compiler source reached its bootstrap AST bound during development.
Packed runtime byte resources now use ASCII hex strings and the existing LZ
history decoder, rather than an AST expression for every encoded byte. The
readable runtime and its locked revision are unchanged. Temporary experiments
with larger workspaces were discarded; the original workspace bounds remain.

## Limits

This closes the nine named observations, not every possible composition of
these mechanisms. Structural expansion and analysis retain bounded workspaces;
unsupported proof or lowering shapes remain distinguishable from rule violations.
Through-result reservations were exercised with aggregate results and mutable
receivers; this cycle makes no universal claim for arbitrary result shapes.
No normative rule was relaxed to make a fixture pass.

Other-platform execution, the full historical corpus, mutation campaigns and
an independent audit were not performed in this cycle. Windows ARM64 execution
remains deferred by the existing user decision. The completed targeted runs are
not a general safety proof. Existing broader platform evidence remains separate.
