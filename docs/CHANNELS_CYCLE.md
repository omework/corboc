# Bounded channels integration

Scope: STD/runtime API plus private scheduler integration and general owned-Option
Future lowering. No grammar change and no Rust-frontend changes.

## Implementation

- Added `std::sync::channel::Channel<T>` and `std::sync::asyn::channel::Channel<T>`,
  with positive capacity, FIFO `send`/`recv`, synchronous idempotent `close`, and
  `SendError.Closed { value }` preserving ownership on failed sends.
- Managed dedicated ring storage follows the active region-size limit and lives
  until channel destruction. The ordinary typed STD destructor drains values;
  the erased runtime does not guess a payload type or destructor.
- Native condition waits block threads. Async operations use stable private
  Future wait records, a readiness epoch, FIFO notification, and unlink/forward
  on frame cleanup. Notifications schedule roots without polling under lock.
- Preserved channel layout and waiter authentication through specialization;
  thread-transfer restrictions apply to payloads, including owned field chains.
- Added general deferred owning `Option<T>` result encoding through the existing
  Future machinery. Dependency-bearing output paths remain separate. Owning
  Result envelopes can contain destructor-bearing enum payloads.
- Updated the retained C reference, STD/runtime documentation and EN/FR README.

## Current integration bounds

Payloads are primitives or autonomous fixed-layout nominal structs/enums,
including user destructors. Borrowed payloads and values requiring external
pool/region/task dependency summaries are refused; their provenance must not be
hidden by the erased queue. This limitation is explicit in the API documentation.
There are no endpoint counts, zero-capacity rendezvous, cancellation API or
strict acquisition fairness guarantee. Consumer loops expecting `None` require
an explicit close. The bounded shared channel itself cannot outlive its owner.

## Reproduction

Language repository:

```sh
python3 scripts/validate_channels_runtime.py --compiler ../corboc/build/channels/corboc-final
python3 scripts/stdlib_docs.py --check
```

Compiler repository:

```sh
python3 scripts/validate_channels.py --compiler build/channels/corboc-final
python3 scripts/validate_mutex.py --compiler build/channels/corboc-final
```

For platform checks, compile the two runtime witness C files and the three public
API C files with `zig cc -target x86_64-linux-gnu -pthread -O1` or
`-target x86_64-windows-gnu`, then execute with Docker/Wine. Use
`-target aarch64-windows-gnu` for the deferred-execution link check. Runtime source
and generated byte resources are linked by `corbo.lock`; installed rebuilding
uses the committed STD/runtime revision.
